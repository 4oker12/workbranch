# Subscriber Locator / Adaptive Route Advisor

## Назначение

Workbench ведёт оператора к состоянию, в котором Billing готов сформировать корректный штатный опрос ONU.

Для PON ключевые поля Billing:

- OLT;
- ONU S/N;
- ONU MAC.

Отдельно хранится **MAC устройства абонента / роутера**. Это не ONU MAC. Он используется как независимый сетевой след, если Billing и ТМЦ не дают достаточного или согласованного ответа.

Guide сверяет технические данные по полям, а не одной общей подсветкой:

| Поле | Для чего требуется |
|---|---|
| Тип подключения | Определяет технологическую ветку и обязательные ONU-идентификаторы |
| MAC устройства абонента | Резервный след для прямого MAC-поиска и UPLINK/DOWNLINK |
| OLT | Нужна для PON-маршрута и штатного опроса |
| ONU MAC | Обязательный идентификатор EPON; дополнительная сверка для других PON |
| ONU S/N | Обязательный идентификатор GPON/GCOM/Huawei; дополнительная сверка для EPON |

Для каждого поля Guide показывает `заполнено`, `отсутствует`, `конфликт`, `условно` или `дополнительно`. Просмотренные доказательства получают спокойную метку, которая восстанавливается при возврате к текущему абоненту.

## Источники

```text
1. Billing → Технические данные
2. UserSide → ТМЦ
3. MAC устройства → история MAC на оборудовании
4. MAC устройства → UPLINK/DOWNLINK (если прямой поиск пуст)
5. Найденное оборудование / интерфейс → уточнение OLT и ONU
```

Источники не равнозначны и не выкладываются оператору одновременно. Workbench может собрать часть фактов фоново, но Guide раскрывает только тот факт и то действие, которые нужны на текущем шаге.

## Стартовая матрица Billing

Порядок полей не важен. Состояние определяется наличием трёх значений: `OLT / S/N / ONU MAC`.

| OLT | S/N | ONU MAC | Следующий шаг |
|---|---|---|---|
| ✓ | ✓ | ✓ | Штатный опрос текущей связки |
| ✓ | ✓ | — | ТМЦ: найти/подтвердить ONU MAC |
| ✓ | — | ✓ | ТМЦ: найти/подтвердить S/N |
| — | ✓ | ✓ | ТМЦ: определить OLT |
| ✓ | — | — | ТМЦ: добрать S/N + ONU MAC |
| — | ✓ | — | ТМЦ: добрать OLT + ONU MAC |
| — | — | ✓ | ТМЦ: добрать OLT + S/N |
| — | — | — | ТМЦ: попытаться восстановить всю связку |

Таким образом, только состояние `✓/✓/✓` допускает прямой опрос без предварительного похода в ТМЦ.

## Ветка ТМЦ

### ТМЦ закрыла пробелы без конфликта идентичности

```text
Billing incomplete
→ TMC found
→ недостающие значения найдены
→ вернуться в Billing
→ подсветить только поля, которые требуется сверить/заполнить
→ оператор сохраняет вручную
→ Workbench повторно читает сохранённые значения
→ штатный опрос
```

Workbench не записывает значения в Billing автоматически.

### OLT Billing отличается от ТМЦ, а ONU S/N/MAC не конфликтуют

Это целевая коррекция OLT:

```text
identity compatible
+ OLT mismatch
→ показать фактическую OLT из ТМЦ
→ вернуть в Billing
→ исправить OLT
→ сохранить
→ опросить
```

### S/N или ONU MAC Billing конфликтуют с ТМЦ

ТМЦ недостаточно, чтобы автоматически считать одну сторону правильной.

```text
ONU identity conflict
→ не предлагать слепое исправление
→ взять MAC устройства абонента
→ прямой MAC history
```

### ТМЦ отсутствует / не распознана / не закрыла пробелы

Если есть MAC устройства:

```text
TMC insufficient
→ direct device-MAC search
```

Если пригодного MAC устройства нет — `manual_review` / отдельная будущая ветка восстановления.

## Ветка MAC устройства

### Прямой поиск дал PON-кандидата

```text
MAC устройства
→ оборудование + порт + VLAN
→ подтвердить MAC на найденном интерфейсе
├─ IP OLT отсутствует → «Открыть OLT и посмотреть IP»
└─ IP OLT есть        → «Вернуться к абоненту»
```

Guide не открывает OLT автоматически. Переход выполняется только по явному нажатию кнопки, когда IP действительно отсутствует. Видимая карточка результата не закрывается из-за фонового пересчёта Locator: она остаётся до действия оператора, закрытия, навигации или исчезновения целевого блока.

### Прямой поиск пуст

```text
MAC direct NOT_FOUND
→ «Искать и на UPLINK/DOWNLINK-портах»
```

Если расширенный поиск дал кандидата, дальше используется та же цепочка `interface → device`.

### OLT и порт найдены, но ONU S/N / ONU MAC всё ещё неизвестны

Это не состояние готовности:

```text
OLT/port found
+ missing ONU identity
→ INSPECT_ONU_DETAILS
→ добрать S/N и/или ONU MAC на найденном оборудовании/порту
```

Только после этого можно возвращаться в Billing и готовить штатный опрос.

### Прямой и UPLINK/DOWNLINK поиск пусты

Для текущего этапа:

```text
MAC direct NOT_FOUND
+ MAC topology NOT_FOUND
→ manual_review
```

Редкие случаи длительной неактивности, удалённой ONU, переноса линии, замены оборудования/арендатора и восстановления по историческим косвенным данным оставлены отдельным будущим слоем.

## Результат штатного опроса

### confirmed

Терминальный результат `confirmed`.

### not_found

Отрицательное доказательство только для конкретной текущей привязки. После этого Workbench идёт в ТМЦ, а не делает вывод, что ONU вообще отсутствует.

### timeout / olt_unreachable

Не отвергают привязку. Допускается один повтор, после чего используются независимые источники.

### conflict

Требует сверки идентификаторов/топологии.

### parser_error

Не превращается в предметный диагноз. Маршрут останавливается как `manual_review`.

## Progressive disclosure

Фоновый сбор и операторская подсказка — разные слои.

Workbench может заранее знать:

- TMC candidate;
- найденную OLT;
- MAC-history candidate;
- интерфейс;
- другие факты.

Но LIVE-панель не должна превращаться в готовый ответ до того, как маршрут дошёл до соответствующего шага.

Принцип:

```text
background facts = evidence cache
Guide = only current next step
```

Например, если Billing полностью заполнен, оператор сначала получает подсказку выполнить штатный опрос. Фоновая TMC-кандидатура не показывается. Она раскрывается только если результат опроса потребовал перехода к ТМЦ/альтернативному поиску.

## Безопасность изменения Billing

- никаких автоматических записей в поля;
- Workbench подсвечивает только необходимые поля;
- оператор сверяет и изменяет их вручную;
- после нажатия «Сохранить» Workbench повторно читает новую страницу;
- только подтверждённо сохранённая комбинация допускается к финальному опросу.
